# 同坑雷達與尋找夥伴

## 範圍與狀態

本功能已於 2026-10-30 部署正式 GCP API 與 App Web。專用 QA 帳號已完成正式 API 與 Android 模擬器的作品探索、夥伴名片及同坑提示驗證。原生 App 需安裝新版才能顯示新介面，詳見[部署與驗證紀錄](../deployment/partner-discovery-2026-10-30.md)。

「同好」頁的「尋找夥伴」入口先列作品，再開啟該作品的夥伴清單。舊 `/api/social/same-works` 保留供既有客戶端使用，不再代表新入口的畫面或排序規則。

2026-11-02 新版 App 調整同好頁四個主分頁為等寬。進入「尋找夥伴」也保留大標題、統計卡與底部導覽，內容區域維持和其他三個分頁相同的高度與比例，不因切換而放大。此版面修正需更新 App；GCP Web 尚未同步發布。

## 公開名片的同坑雷達

查看他人公開名片時，前端讀取目前登入者的坑單，以作品 ID 比對雙方的 `pitWorks`、`deepPitWorks` 與 `shallowPitWorks`。深坑與淺坑交叉比對，同一作品 ID 只計一次，空 ID 不列入；作品名稱相同而 ID 不同不算同坑。

有交集時顯示「同坑雷達！你們有 N 部共同作品」。對方深坑與淺坑中的共同作品標籤使用高亮、雷達圖示及「與我同坑」無障礙語意，仍保留原本的深淺坑分組。

訪客、自己的名片及沒有交集時不顯示提醒。登入者資料載入中或讀取失敗時不顯示匹配結果，也不宣稱沒有共同作品。失敗時他人名片的坑單提供「重新讀取同坑雷達」。讀取依工作階段版本區分，切換帳號後重新取得登入者資料。

## 尋找夥伴的作品範圍與人數

兩個分頁各自保留已提交的搜尋字串，初始顯示「與我同坑」。作品清單依資料庫的作品名稱升序，再依作品 ID 升序排列，不按夥伴人數排序。

| 分頁 | API scope | 收錄規則 |
| --- | --- | --- |
| 與我同坑 | `mine`，也是 API 預設值 | 目前帳號深坑與淺坑的作品，包含零位夥伴的作品。沒有坑單時為空。 |
| 看看大家坑什麼 | `all` | 至少有一位合資格其他使用者的作品，可包含自己未加入坑單的作品。沒有坑單也可探索。 |

作品卡顯示作品名稱與 `partnerCount`，自己已加入的作品另標示「我的坑」。`partnerCount` 計算該作品的不重複合資格其他使用者，深淺坑不分開計數，同一人只算一次。

合資格使用者排除自己、非 `active` 帳號、沒有公開名片碼及任一方向封鎖者。只有自己、只有不合資格使用者或無人加入的作品，不列入 `all`；自己的作品仍可列入 `mine` 並顯示零位夥伴。既有關注或戳友關係不是排除條件。

搜尋以作品名稱包含字串比對，按搜尋鍵提交後才查詢，不搜尋使用者暱稱。前後端上限均為 100，後端按字串長度檢查；`%`、`_` 與 `!` 作一般字元處理，不作萬用字元。大小寫與名稱排序依資料庫定序規則。

## 選作品後查看夥伴

點作品卡開啟該作品的夥伴清單。人選必須有該作品，不要求目前帳號也有該作品；按使用者 ID 升序排列，同一人只列一次，不按共同作品數排序。

每人回傳名片基本資料及雙方全部共同作品，不只所選作品。雙方沒有交集時 `commonWorkCount` 為零、`commonWorks` 為空，仍可列在所選作品的人員清單。畫面只在共同作品數大於零時顯示共同作品摘要。

「查看名片」開啟公開名片。「戳友」沿用自我介紹與選填場次邀請流程，不自動關注或接受好友，也不向邀請者揭露忽略狀態。已送出、已是戳友、收到邀請各自顯示對應狀態；收到邀請可由「確認邀請」開名片。戳友狀態尚未成功載入時停用邀請，讀取失敗提供重試。

## API 契約

新舊端點皆在登入驗證及目前程式的社群同意 middleware 之後註冊。回應設定 `Cache-Control: private, no-store`。沿用 `works`、`user_pit_works`、`users` 與 `user_blocks`，本功能不新增 schema migration。

### 作品清單

`GET /api/social/partner-works?scope=mine&q=&offset=0&limit=20`

```json
{
  "items": [{"id": "100", "name": "作品", "partnerCount": 2, "isMine": true}],
  "hasMore": false,
  "nextOffset": null
}
```

`scope` 僅接受 `mine` 或 `all`，預設 `mine`。`q` 預設空字串，不可為重複參數形成的陣列或超過 100 長度的字串。非法值回傳 400，錯誤分別為 `invalid_scope`、`invalid_search`。

### 作品的夥伴清單

`GET /api/social/partner-works/:workId/users?offset=0&limit=20`

```json
{
  "items": [{
    "userId": "2",
    "publicCode": "PUBLIC_CODE",
    "nickname": "同好",
    "avatarUrl": "",
    "bio": "",
    "commonWorkCount": 1,
    "commonWorks": [{"id": "100", "name": "共同作品"}]
  }],
  "hasMore": false,
  "nextOffset": null
}
```

`workId` 必須是十進位正整數且不超過 JavaScript 安全整數上限，非法值回傳 400 `invalid_work_id`。合法但不存在、無人加入或沒有合資格人選的作品回傳空頁。每頁先取得人選，再一次讀取該頁的共同作品，不逐人查詢。不回傳 Email、登入憑證、活動出席或現場位置。

兩個新端點預設 `offset=0`、`limit=20`，`limit` 範圍 1 至 50，`offset` 範圍 0 至 100000。參數只接受十進位整數字串，負數、小數、重複參數及超界值回傳 400 `invalid_pagination`。前端每次請求 20 筆，依 `hasMore` 與 `nextOffset` 載入更多；新端點不回傳超過 offset 上限的下一頁位置。

### 舊同坑人員清單相容性

`GET /api/social/same-works?offset=0&limit=20` 保留原回應格式，與上述人員頁相同。深坑、淺坑都納入共同作品 ID 比對，按共同作品數由多至少，再按使用者 ID 升序排列。排除條件相同；沒有交集回傳空頁，不改列所有使用者。

舊端點預設 20 人、最多 50 人，offset 上限 100000，非法分頁參數回傳 400。新入口使用兩個 `partner-works` 端點，不以舊清單代替「看看大家坑什麼」。

## 載入、重新整理與隱私

作品清單與人員清單都有載入、錯誤重試、空狀態、下拉重新整理及載入更多。搜尋無結果、自己沒有坑單、沒有可探索作品及作品沒有可顯示夥伴各有空狀態。載入更多失敗保留原內容與下一頁位置，可重試；追加時按作品 ID 或使用者 ID 去重。

搜尋範圍及字串各有獨立 provider；重新整理、provider 銷毀或工作階段改變後，舊的載入更多結果不得追加到新清單。修改個人坑單、更新社交關係及社交頁相關重新整理會使探索資料失效後重讀。

同坑提醒及探索人數只反映坑單，不授予戳友、活動出席或位置可見權限。服務端在作品計數與人員清單都套用同一雙向封鎖及帳號資格條件，不能只靠前端隱藏卡片。
