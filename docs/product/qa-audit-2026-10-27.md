## 優先修正

### Q01 / P1 / 名片儲存可能跨帳號寫入

帳號 A 按儲存後，若照片仍在上傳，此時登出並登入 B，A 的舊儲存流程可能使用 B 的新憑證送出名片更新。`mounted` 檢查在更新之後，無法阻止寫入。

依據為 [profile_page.dart:349](/Users/frank/FlutterProjects/coscircle/lib/features/profile/presentation/profile_page.dart:349)、[api_client.dart:42](/Users/frank/FlutterProjects/coscircle/lib/core/api/api_client.dart:42) 及 [server.js:530](/Users/frank/FlutterProjects/coscircle/backend/src/server.js:530)。後端 handler 在記憶體資料中確認會更新當下憑證對應的使用者。帳號切換的完整手機時序尚未重現，不能宣稱正式資料已發生混寫。

修正驗收應涵蓋延遲上傳期間切換帳號。A 的未完成操作不得修改 B，登出後的舊請求也不得重試到新帳號。

### Q02 / P1 / 封鎖後仍能讀取共同小圈圈的集合地點

A 與 B 在同一小圈圈時，無論誰封鎖誰，集合查詢仍回傳對方建立的集合座標、建立者、時間與說明。查詢只驗證小圈圈成員資格，沒有排除封鎖關係。這是使用者選定的集合地點，不是已證實洩漏即時 GPS。

依據為 [server.js:2052](/Users/frank/FlutterProjects/coscircle/backend/src/server.js:2052) 及 [server.js:1878](/Users/frank/FlutterProjects/coscircle/backend/src/server.js:1878)。實際 SELECT 在記憶體 SQLite 中重現兩種封鎖方向及兩種查看方向。沒有讀取正式使用者座標。

修正驗收應同時確認 API 回傳及地圖呈現，不能只在前端藏掉標記。
