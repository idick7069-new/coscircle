# curl_cffi event transport

The Node event importer calls `backend/scripts/curl-fetch.py` for Doujin,
COSMOS and acosta HTML. Parsing, deduplication and database imports remain in
Node. Axios remains a backend dependency for unrelated API integrations.

Both layers refuse source requests outside `coscircle-free-vm`. Python permits
only the three approved HTTPS source hosts, verifies TLS, identifies itself as
CosCircleBot, disables environment proxies and redirects, and makes one request
per call. An explicitly configured DataImpulse proxy may be used for Doujin only.
Doujin uses `impersonate="chrome"` with `default_headers=True` from the pinned
curl_cffi release. Chrome User-Agent/Accept/client-hint headers are generated by
the library, not copied manually. The client identifies itself using
`X-CosCircle-Client: CosCircleBot/1.0 (+https://coscircle.app)`. Other sources retain
their Bot User-Agent and do not use a browser profile. No profile rotation,
custom fingerprint overrides or challenge
solving is enabled.
403, 429 and Cloudflare challenges are not retried or sent to browser fallback.
408 and 5xx supplemental responses retain the existing bounded retry policy.

## GCP prerequisite

Before deploying this change, install the Python dependency on the production
VM through SSH. Do not run the source fetcher from a local/public network.
These commands run on `coscircle-free-vm`, project `cos-circle`, zone
`us-west1-b`, not on the developer workstation:

```bash
sudo apt-get install -y python3-venv
candidate=/opt/coscircle/api/releases/YOUR_CANDIDATE_RELEASE
sudo python3 -m venv "$candidate/.crawler-venv"
sudo "$candidate/.crawler-venv/bin/python" -m pip install \
  -r "$candidate/scripts/requirements-crawler.txt"
sudo -u coscircle "$candidate/.crawler-venv/bin/python" -c \
  'import curl_cffi; print(curl_cffi.__version__)'
```

The requirements file must first be included in the candidate release. Do not
switch the production release before the dependency check succeeds. Existing
deployment packaging already includes the `scripts` directory. The default
interpreter is `.crawler-venv/bin/python` within each backend release; a different absolute
path can be configured with `EVENT_SCRAPER_PYTHON` in the service environment.
Missing Python/dependency is a source failure, never an empty successful import.
The full deployment script installs the pinned crawler dependency before
switching the API release. Bootstrap includes `python3-venv`. Old releases keep
their own dependency environment, so a rollback does not inherit the upgrade.

## Authorized DataImpulse connection

The project owner reported that Doujin permits reuse of its event information
with source attribution. The importer retains `sourceName` as `同人誌中心` and
the original event URL; the app displays both the source label and source link.
No source access is attempted from the developer workstation.

Optional proxy credentials are stored solely on GCP in
`/etc/coscircle/dataimpulse.json`, owned by `root:coscircle` with mode `0640`.
This file is not included in releases, Git or frontend assets. Only Doujin uses
it; other sources remain direct. An invalid existing configuration fails closed
without falling back to direct requests or a browser. A missing/disabled file
keeps direct transport. No automatic identity switching, challenge
solving or retry following 403/429 is added.

To set or replace credentials, use an interactive SSH terminal on the VM:

```bash
sudo python3 /opt/coscircle/api/current/scripts/configure-dataimpulse.py
```

Enter the proxy login and proxy password from your purchased plan's Proxy Access
section, not the DataImpulse account password. Both are hidden during entry.
The tool writes the configuration atomically and never prints credentials.
The fetcher rereads this file per request, so credential replacement does not
require restarting the API. The endpoint must use the official gateway host;
credentials are passed separately rather than embedded in a URL or CLI arguments.

References: [DataImpulse connection hosts](https://docs.dataimpulse.com/proxies/connection-hosts),
[proxy authentication](https://docs.dataimpulse.com/authentication-methods/user-pass-authentication).
